## 4. Android（模拟器 emulator-5554）

### 4.1 构建与安装

`flutter build apk --release --split-per-abi` 成功（armeabi-v7a / arm64-v8a / x86_64），安装 `app-x86_64-release.apk`。

收尾中发现并修复的两个 release 问题：

1. **启动即崩溃**：R8 删除 / 改名了 shared_preferences_android 2.5、path_provider_android 2.3 经 package:jni 反射调用的方法和
   Kotlin 运行时类（`NoSuchMethodError … SharedPreferencesApiRegistrar.getAll`、`ClassNotFoundException kotlin/Result$Failure`）。
   新增 `android/app/proguard-rules.pro`。
2. **音频无法启动**：AAudio 默认设备是伪设备 `aaudio:-1`，不在设备枚举里，音频线程按 id 重新查找失败。`up-host` 先匹配默认设备。

## 5. Hub 端到端（Linux 桌面 Hub ↔ Android 模拟器客户端）

方法：桌面运行 release 版应用（Xvfb），`ULTRAPADS_HUB_AUTOSTART=UltraPads-Desk ULTRAPADS_LOG_EVENTS=1 ULTRAPADS_ROUTE=/hub`，
stdout 打印端口（47100）与配对码；模拟器在 Hub 页「手动输入地址」填 **`10.0.2.2:47100`**。模拟器在 NAT 后，宿主的 mDNS
不可达，因此只走手动地址；控制面 TCP 与控制器 UDP 都由模拟器主动发起，经模拟器 NAT 到达宿主机、回包可返回，
**不需要 `adb forward` / `adb reverse`**。

| 步骤 | 结果 | 证据 |
|---|---|---|
| 手动地址 probe | 显示 `ULTRAPADS-DESK 10.0.2.2:47100` | `android-hub-manual-address.png`、`android-hub-probed.png` |
| 重启后 | 手机重启应用后仍记得已配对的 Hub（peers.json），可直接同步 / 控制 | — |
| 配对（输入桌面配对码） | 成功；双方受信列表各多一台；桌面 `HubPeerPaired UltraPads android` | `android-hub-pair-dialog.png`、`android-hub-paired.png`、`linux-hub-desktop-events.log` |
| 同步 | 第一轮显示进度「Syncing 9 of 9」；第二轮（修复后、全新数据）「Sync finished: 1 downloaded, 0 uploaded」，桌面仍为 8 个 Kit | `android-hub-syncing-progress-run1.png`、`android-hub-syncing.png`、`android-hub-sync-finished.png` |
| 控制器 | 演奏页出现「CONTROLLING ULTRAPADS-DESK」状态条；手机按 pad，桌面引擎 `pad … playing` 与非零电平；本机默认不发声 | `android-controller-mode.png`、`linux-hub-remote-controller.png`、`linux-hub-desktop-events.log` |
| 往返延迟 | 控制器卡片显示「Round trip 2 ms」（模拟器 NAT 回环，不代表 Wi-Fi 跨设备数据） | `android-hub-controller-card.png` |
| 本机同时发声 | 打开后手机与桌面同时播放 | `android-hub-controller-local-echo.png`、`android-controller-local-echo-playing.png` |
| 退出控制器 | 状态条消失，桌面 `HubRemoteControllerChanged connected=false`（并补发 pad_up） | `android-controller-exited.png` |

联调中发现并修复：两台设备各自首次导入内置 Kit 后第一次同步，CC0 Kit 因 manifest 中的导入时间不同生成 `~conflict~`
副本，原 App Kit 因随机 ID 重复为两份（桌面曲库从 8 个变成 16 个）。修复（`362f3c5`）：导入保留包内时间戳、原 App Kit
使用确定性 ID；用两个全新数据目录重测，同步后两端都是 8 个 Kit，只传输了新增的作品。

同一台 Linux 上的两进程 / 集成测试：`cargo test -p up_ffi --test ffi_hub`（服务、配对、同步、控制器转发）通过。

## 6. 已知问题

### v0.0.1 已知限制

1. 真机未验证：Android 只在 x86_64 模拟器上验证（音频输出为模拟器设备，判定以引擎事件为准）；arm64 / armv7 包只构建未安装。
2. 模拟器无法收到宿主的 mDNS，跨 NAT 只能手动输入 `10.0.2.2:<端口>`；同一 Wi-Fi 下的真机发现未验证。
3. 作品播放只有开始 / 结束事件，TRACK 卡上没有实时播放进度。
4. 原 App Kit 的描述文字由 Rust 导入器写入（中文），英文界面下也显示中文。
5. 首次引导浮层的 SKIP 位于右上角，会盖住视频按钮（4.7.0 的 SKIP 也在右侧，浮层期间按钮本就不可点）。
6. 宽屏时顶栏和功能行与 pad 网格同宽；4.7.0 iPad 截图中顶栏铺满全宽，两者不一致，留待确认。
7. image 类皮肤位图按 `BoxFit.fill` 拉伸，未做九宫格；小装饰图（Christmas 鼻子、Halloween 幽灵等）未放；tint / scale 类皮肤仍只用 token。
8. 视频按钮按界面语言（不是地区）选择 BiliBili / YouTube。
9. `ffi_hub` 集成测试在机器满载时可能超时（见 §2）。
10. 未验证：Windows、macOS、iOS、Web、插件（ADR-0001 #25）。
